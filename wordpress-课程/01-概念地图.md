# 01 · 概念地图：一个网页到底是怎么到你眼前的

> 这一节不安装任何东西，只建立模型。**建成这层模型，后面所有报错你都能自己定位到层**。
> 读完的验收：不看文档，讲清"我点开一篇文章时发生了什么"。

## 一、一次访问的 7 个环节

```
[1] 你输入 blog.yurucamp.vip
      ↓
[2] DNS 解析：域名 → 服务器 IP（地址簿查询）
      ↓
[3] 建立连接（HTTPS 握手，证书校验）
      ↓
[4] 请求到达 Web 服务器（Nginx / Apache）
      ├─ 静态文件（图片/CSS/JS）→ 直接返回
      └─ .php 请求 → 交给 PHP 解释器
      ↓
[5] PHP 执行 WordPress 代码
      ↓
[6] WordPress 查 MySQL 数据库（文章标题、正文、评论…）
      ↓
[7] PHP 用主题的模板把数据"套"成 HTML 返回
      ↓
[8] 浏览器解析 HTML → 下载 CSS/JS/图片 → 绘制成页面
```

记住三个角色的分工，后面调试时你会反复用到：

| 层 | 负责 | 出错时的典型症状 |
|---|---|---|
| Web 服务器 | 收请求、给静态文件、转发 PHP | 502/504、404、图片不显示 |
| PHP + WordPress | 业务逻辑、查库、拼页面 | 白屏、500 错误、`There has been a critical error` |
| 数据库 MySQL | 存所有内容 | "建立数据库连接时出错"、文章全消失 |
| 浏览器 + CSS/JS | 排序、上色、动画、交互 | 页面能显示但错位、按钮点了没反应 |

**这张表就是你的排查顺序表**：先问"是整站打不开，还是只有某个页面不对"，答案会直接指向不同层。

## 二、WordPress 到底是什么

一句话：**WordPress = 一个把"内容（存在数据库里）"和"外观（主题文件）"分开的 PHP 程序。**

它的身体分三块，你必须都知道在哪：

```
WordPress 安装根目录/
├── wp-admin/         后台界面代码（别动）
├── wp-includes/      核心函数库（别动）
├── wp-content/       ★ 你的地盘
│   ├── themes/           主题（决定长什么样）
│   ├── plugins/          插件（加功能）
│   └── uploads/          你上传的图片，按年月存放
├── wp-config.php     ★ 数据库账号密码、密钥都在这
└── .htaccess         Apache 的重写规则（Nginx 则在站点配置里）
```

**你 99% 的时间只碰 `wp-content` 和后台。** 核心文件永远不要手改——WP 自动更新会覆盖。

数据库里存什么：`wp_posts`（文章/页面/菜单项/修订版本都在这张表）、`wp_options`（站点设置、主题选项）、
`wp_users`、`wp_comments`、`wp_term_relationships`（文章和分类的关系）。
**数据库才是唯一真相**：删了文件可以重下，删了数据库就等于内容全没。

## 三、前端三件套：各自负责什么，你要学到哪

| 语言 | 负责 | 在 WP 里藏在哪 | 你的学习深度 |
|---|---|---|---|
| **HTML** | 结构：这是标题、这是段落、这是图片 | 主题的 `header.php`/`single.php` 等模板的输出 | 认识 15 个常用标签即可，不要求能手写整页 |
| **CSS** | 样式：颜色、间距、圆角、阴影、排版、动画 | 主题的 `style.css` 与 `assets/*.css` | **要真的会**：复刻的差距 90% 在这一层 |
| **JavaScript** | 行为：点击、滚动、无刷新跳转 | 主题的 `*.js` | 先读懂别人的，会改参数即可，不要求从零写 |

一个最小例子，看清三者关系：

```html
<!-- HTML：结构与语义 -->
<article class="card">
  <h2>第一篇文章</h2>
  <p>正文…</p>
</article>
```

```css
/* CSS：选中 .card，给它白底、圆角、阴影 */
.card { background:#fff; border-radius:8px; box-shadow:0 2px 4px rgba(0,0,0,.075); }
.card:hover { box-shadow:0 8px 16px rgba(0,0,0,.12); }   /* 鼠标悬停时换一种阴影 */
```

```js
// JS：让上面那个 hover 之外，点击卡片标题时字母间距变大
document.querySelector('.card h2')?.addEventListener('click', e => e.target.style.letterSpacing = '1px');
```

## 四、PHP：你只需要懂 5 件事

不要被"要学一门后端语言"吓住。读 WordPress 主题时，90% 的 PHP 只是这五件事：

```php
<?php
// 1) 输出内容（模板里最常见）
the_title();                    // 打印文章标题
echo esc_html( $some_var );     // 打印一个变量（esc_html 是安全处理）

// 2) 条件判断
if ( have_posts() ) { /* 有文章时显示 */ } else { /* 没有时 */ }

// 3) 循环
while ( have_posts() ) { the_post(); the_content(); }

// 4) 函数调用 / 取数据
$cats = get_the_category();

// 5) 引入别的文件
get_header();  get_sidebar();  get_footer();
?>
```

够用了。真要写功能时，你是"查函数名 + 拼起来"，不是背语法。

## 五、模板层级：WP 怎么决定用哪个文件渲染

这是 WordPress 最优雅也最容易被忽略的设计。简化版：

```
首页文章列表      → home.php  → index.php（兜底）
单篇文章          → single.php → singular.php → index.php
固定页面          → page.php
分类列表          → category.php → archive.php → index.php
搜索结果          → search.php
404              → 404.php
```

每个模板又都由 `header.php` + 内容 + `footer.php` + `sidebar.php` 拼成。

**为什么你要懂这个**：想改"文章页标题的位置"，你要改的是 `single.php`；
想改"所有页面共用的顶栏"，改 `header.php`；想改"全站兜底样式"，改 `style.css`。
没有这层地图，你只会在后台到处乱点。

## 六、钩子（Hook）：不改别人代码也能插一脚

WP 生态能这么繁荣，靠的就是这个。两种：

```php
// action：在"某个时刻"插入一段代码（比如页脚打印前）
add_action( 'wp_footer', function () {
    echo '<div style="text-align:center">本站由我亲手搭建</div>';
} );

// filter：把"某个值"改掉再交回去（比如把摘要长度从 55 词改成 30 词）
add_filter( 'excerpt_length', function () { return 30; } );
```

这两段代码写在哪？**写在你子主题的 `functions.php` 里**（文件 04 会带你建）。
只要懂了 add_action / add_filter，你就能在不碰主题源码的前提下改几乎任何东西。

## 七、五个必须现在就纠正的误解

1. **"WordPress 是拖拽建站工具"** —— 不是。它是 CMS：可视化编辑的是**内容**，观感由主题的代码决定。
   想要"拖拽任意摆放"，那是 Elementor 这类页面构建器插件的功能，代价是变慢、变重。
2. **"在后台直接改主题代码很方便"** —— 主题一升级，改的全丢。永远用子主题。
3. **"插件越多功能越强"** —— 插件越多，加载越慢、冲突概率越高、被攻击面越大。常见站 5～10 个插件就够。
4. **"文章和页面差不多"** —— 文章（post）有分类/标签/时间线，会出现在列表；页面（page）是"关于我"这种固定内容，不进列表。
5. **"换主题就等于换个样子，内容还在"** —— 内容确实在（数据库里），但主题选项通常不通用，你之前的配置**要重配**。

## 验收（讲给我听）

1. 从输入域名到看到页面，中间经历了哪 5 个环节？其中哪一步出错会导致"整站打不开"？
2. `wp-content` 下三个目录各放什么？
3. 我想改"所有页面的顶栏"，该动哪个文件？想改"文章页正文"，动哪个？
4. 为什么不能直接在父主题里改 CSS？

答不上来就回去重读对应小节——这是后面所有操作的地基。
